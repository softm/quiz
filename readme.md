문항영역 맵 계산/표시 정리	문항영역 생성 기준, 생성 안 했는데 표시되는 이유, 높이 계산 이상, 문항 앵커 원 기준 제안	저장된 문항영역이 없으면 문항 앵커 기준으로 임시 표시하고, 편집한 것만 저장되게 명확화
앵커맵/문항영역 초기화 의미 정리	위치맵 삭제 시 삭제 범위, 전체 영역 초기화와 위치맵 삭제 관계, 문제/문항 단위 초기화	초기화/삭제가 무엇을 지우는지 명확히 분리하고, “초기화는 삭제가 아니라 기준 상태 복원”으로 UX 정리
정답 파일 연결 상태 정의	목록의 “정답 파일 연결” 의미, 어떤 근거로 연결 판단하는지, 언제 정상인지	목록/상세에서 정답 파일 연결 판단 기준을 일관되게 정의
correct.json 생성/재생성 흐름	문제 상태 초기화 후 correct.json 재생성, 정답 JSON 생성 로직 표, 정답파일 찾는 기준 도입, API 404	정답 파일 탐색 기준 → correct.json 생성 → 상세/풀이 화면 연결까지 관리자 흐름 정립
게시 가능 조건 정리	정답 연결 안 되면 게시 불가, OCR 오류면 앵커맵 필요, 게시 상태가 맞는지 질문	게시 조건을 정답 연결 필수 + OCR 오류 시 앵커맵 필수로 고정
풀이 화면 정답 표시 검증	correct.json 생겼는지, 풀이화면 정답 표시 안 됨	correct.json 존재/연결/풀이 화면 표시까지 end-to-end 검증
채점 표시 용어 정리	정답 언더라인, 오답 스트라이크 용어 제안	채점 UI 상태명을 통일해서 화면/문서/코드에서 같은 표현 사용
회귀 방지 기준	“또 반복되네”, 해결됐던 문제가 다시 발생	앵커 편집 변경 후 고정 체크리스트를 만들고 전체보기/2단/스크롤락/문항영역 복귀를 반드시 검증
